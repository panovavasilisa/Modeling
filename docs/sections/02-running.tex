\section{Сборка и использование}
\label{sec:running}

\subsection{Текущая точка входа}
Итоговый проект находится в \code{/home/toster/prac}. Функция \code{main()}
создаёт \code{QApplication}, окно \code{MainWindow}, вызывает \code{show()}
и запускает цикл событий \code{a.exec()}. Параметры модели передаются из формы,
а не из аргументов запуска. Аргументы \code{--days}, \code{--report},
\code{--quiet} и \code{--orders} в этой точке входа не обрабатываются.

\subsection{Зависимости и сборка}
Необходимы C++17, \code{make}, \code{qmake} и Qt Core, Gui, Widgets.
В проекте указаны \code{QT += core gui widgets}, \code{CONFIG += c++17},
каталоги поиска заголовков корня и \code{back/}, форма \code{mainwindow.ui}.
В исходном \code{PharmDelivery.pro} модуль анимации дважды указан в списках
исходников и заголовков. Следующая команда исключает повторы только при
генерации Makefile, не меняя исходный файл проекта:
\begin{lstlisting}[language=bash]
cd /home/toster/prac
mkdir -p build
cd build
qmake6 ../PharmDelivery.pro -after \
  'SOURCES = $$unique(SOURCES)' \
  'HEADERS = $$unique(HEADERS)'
make -j2
./PharmDelivery
\end{lstlisting}
Для Qt 5 вместо \code{qmake6} используется \code{qmake}.
Обычный запуск требует графической сессии. Текущий \code{main.cpp} не включает
\code{offscreen} автоматически. Для технической проверки создания окна без
экрана можно задать \code{QT_QPA_PLATFORM=offscreen} извне; это не превращает
GUI-программу в консольный обработчик параметров.

\subsection{Передача параметров из окна}
\code{MainWindow::buildParameters()} создаёт \code{SimulationParameters},
заполняет поля, после чего вызываются \code{configure_simulation(p)} и
\code{init_simulation()}. Дневной шаг в \code{MainWindow::doStep()} вызывает
четыре функции backend в порядке из раздела~\ref{sec:model}.
Перед первым шагом используйте подготовку модели или кнопку старта.

\subsection{Отличия текущей формы от возможностей backend}
\begin{itemize}
  \item \code{ordersPerDaySpin}: 1--200, начальное значение 20; это не
        значение 180 из структуры модели.
  \item \code{discountedProbSpin}: проценты 0--100, начальное значение 75;
        перед передачей в backend значение делится на \code{100.0}.
  \item Наценка в форме ограничена 0--100\%, отдельные скидки --- 0--9\%.
  \item Порог пополнения в форме: 1--100; горизонт уценки: 1--90 дней;
        капитал: 0--1000000000 рублей.
  \item \code{regular_customers=10} и \code{seed=5489} задаются кодом формы.
        \code{initial_count=80} и пустой \code{initial_stock_file} остаются
        значениями структуры: поля выбора CSV и seed в текущем окне нет.
\end{itemize}

\subsection{Консольные функции и экспорт}
\code{internal/simulation_cli.cpp} содержит обработчик аргументов,
справку, печать отчётов и запись JSON. Это отдельный служебный модуль;
текущий \code{main.cpp} его не вызывает, а текущий \code{PharmDelivery.pro}
не включает его в приложение.
Для отдельного потребителя модели его можно подключить явно и вызвать
\code{model_detail::parse_command_line()} или
\code{model_detail::write_json_report()}. В штатном окне кнопки экспорта нет.
Пример использования backend без Qt приведён в разделе~\ref{sec:api}.

\subsection{Повторяемость и ошибки}
Одинаковые seed и параметры воспроизводят эксперимент при неизменных коде,
CSV и реализации стандартной библиотеки. Меняется число вызовов генератора ---
может измениться и поток заказов, даже при том же seed.
Backend сообщает о недопустимых параметрах и нарушении фаз через исключения.
Текущие обработчики инициализации и шага окна записывают исключения в журнал.
Фиксированный протокол консольных кодов 0/1 и префикса <<Ошибка:>> для
текущей GUI-точки входа не реализован.
